# Lark 长连接配置 — 收不到消息时的必查步骤

## 现象

长连接脚本显示 `connected to wss://...`，但在群里发消息后：
- 终端**没有**出现 `[BI助手] >>> 收到消息`
- 机器人不回复

说明：**事件没有发到我们的长连接**，多半是 Lark 后台仍使用 Webhook，未切换为长连接。

---

## 两个必须完成的配置（缺一不可）

| 配置项 | 说明 | 常见遗漏 |
|--------|------|----------|
| **① 订阅方式** | 选择「使用长连接接收事件/回调」 | 只添加了事件，忘记改这里 |
| **② 事件配置** | 添加「接收消息 im.message.receive_v1」 | 已添加 ✓ |

---

## 平台与应用必须一致

| 脚本启动方式 | 开放平台地址 | 需配置的应用 |
|-------------|-------------|-------------|
| `--domain lark` | https://open.larksuite.com | 脚本启动时打印的 app_id |
| 无 `--domain`（默认飞书） | https://open.feishu.cn | 同上 |

**请确认**：脚本启动时会打印 `【请核对】当前连接的应用 ID: cli_xxx`，必须在对应平台配置**该应用**。

## 详细步骤（Lark 国际版 open.larksuite.com）

### 步骤 1：保持长连接脚本运行

```bash
python scripts/run_bi_lark_long_connection.py --domain lark
```

看到 `connected to wss://...` 后**不要关闭**，保持运行。

### 步骤 2：登录 Lark 开放平台

打开 **https://open.larksuite.com** → 登录 → 选择你的应用（cli_a930...）

### 步骤 3：编辑「订阅方式」（关键）

1. 左侧菜单进入 **事件与回调**（Event and Callback）
2. 找到 **「订阅方式」** / **「Callback subscription mode」** / **「请求地址」** 相关区域
3. 当前可能是 **「将事件发送至开发者服务器」**（Webhook，需要填 URL）
4. 改为 **「使用长连接接收事件」** / **「Receive callbacks through persistent connection」**
5. 点击 **保存**（Save）

> ⚠️ **必须长连接在线时才能保存成功**。若保存失败，检查脚本是否在运行且已 connected。

### 步骤 4：确认事件配置（关键）

1. 在 **事件配置** 页面，**向下滚动** 到 **「已添加事件」** 区域
2. 确认列表中有 **「接收消息」** / **im.message.receive_v1**（v2.0 版本）
3. 若列表为空或没有该事件：点击「添加事件」→ 搜索并选择 **接收消息**（im.message.receive_v1）→ 保存
4. 若有「发布」或「保存」按钮在页底，点击使配置生效

> ⚠️ 仅选择「使用长连接」不够，必须在「已添加事件」中看到「接收消息」。

### 步骤 5：验证

1. 在机器人所在的群里发：**ping** 或 **测试**
2. 看终端是否出现：`[BI助手] >>> 收到消息 | ...`
3. 若出现且机器人回复「pong」或「收到！」，说明配置正确

---

## 常见问题

- **保存时提示失败**：确保长连接脚本在运行且已 connected
- **找不到「订阅方式」**：可能在「事件与回调」页面的顶部或第一个 Tab
- **发消息给谁**：确保消息是发给该应用的机器人（在群内 @机器人，或与机器人单聊）
