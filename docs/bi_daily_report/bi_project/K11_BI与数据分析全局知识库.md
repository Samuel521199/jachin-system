# K11 游戏平台 — BI 与数据分析全局知识库

> **定位**：面向 **BI 自动化分析系统**、**数据分析师** 与 **业务增长团队**。  
> **取舍**：弱化底层代码与微服务实现，聚焦 **商业变现、用户漏斗、经济流转、风控指标、埋点逻辑** 与 **告警协同**，便于直接用于看板搭建与自动化分析 Agent。  
> **维护**：可与 `K11_Game_Platform_Knowledge_Base.md`、`K11_需求池_干系人.md` 交叉引用。

## 一、商业变现与网赚模型 (Business & Monetization)

平台逻辑为 **「买量网赚（Web-earning）+ 休闲博弈」** 混合模型，强依赖 **ROI 实时监控**。

### 1.1 核心盈利公式

- **前提**：单用户 **LTV（生命周期总价值）> CAC（获客成本）**。
- **双轨收入**：
  - **IAA**：激励视频等（如破产救济看广告）；核心指标 **eCPM**（千次展示收益）。
  - **IAP**：用户在高倍数玩法（如 Crash）中追求期望值的 **水池利润**（固定 RTP 下的抽水）。

### 1.2 目标市场与买量基线（示例：菲律宾 / 印尼）

BI 需重点跟踪 **日消耗与回收**。

| 市场 | 预估 CAC | 预估 eCPM | 单次观看时长（文档示例） |
|------|-----------|-----------|---------------------------|
| 菲律宾 (PH) | 约 $0.4 | 约 $9 | 约 22 分钟 |
| 印尼 (ID) | 约 $0.2 | 约 $6 | 约 16.5 分钟 |

**留存漏斗监控基线（文档给定）**：次留 **40%**，三留 **15%**，七留 **8%**。

## 二、核心数据实体与经济指标 (Data Entities & Economy)

报表换算与清洗需统一遵守以下规则。

### 2.1 货币与汇率

- **唯一主货币**：**金币（Coins）**；**钻石体系已废弃** — 清洗时需过滤历史/脏数据。
- **换算**：**1 PHP = 1,000 Coins**。
- **USD**：随市场浮动；文档参考 **1 USD ≈ 57.16 PHP**。

### 2.2 社交与活跃度（粘性）

| 指标 | 用途 | 规则摘要 |
|------|------|----------|
| **经验值 EXP** | 平台等级（最高 52 级） | **1 金币礼物 = 1 EXP** |
| **魅力值** | 人气榜 | **10 金币礼物 = 1 魅力值** |
| **活跃度** | 开宝箱（至至尊，最高 15,000 金币等） | **每日上限 250 点** |

**活跃度采集规则（文档）**：

- 派对房停留 **10 分钟 = 1 点**；
- 有效发言：**≥3 字** 且 **间隔 ≥5 秒** = **1 点**。

### 2.3 机器人生态与通胀监控

BI 须 **真实用户 vs 机器人流水隔离**，并监控机器人侧水池健康度。

- **离场重置**：**Poor** 机器人离场后金币重置为 **50,000**；**Rich** 为 **250,000**。
- **风控**：局内赢钱超过 **自带上限的 10%** 时 **强制踢出并重置**，避免机器人过度抽干真实用户池。

## 三、用户生命周期与核心转化漏斗 (Funnel & Lifecycle)

### 3.1 新客黄金 120 秒（Golden 120s）

BI 建议单独做 **漏斗视图**，看每一步流失。

1. **游客转化**：广告点击 → 进体验房 → 体验结束（强弹红包雨/大转盘等）→ **120 秒内注册**。
2. **新进首充**：注册完成 → **120 秒内首充**（首充礼包）。

### 3.2 新进破产保护（防流失）

动态破产保护；BI 需重点监控表 **`UserPromotion_Log`**（及触发/策略相关字段）。

**触发因子（文档）**：**Balance**、**WinRate**、**IndividualRTP**、**LoseStreak** 等。

**挽留策略类型（用于转化分析）**：

- **DirectReward**：直接赠币  
- **InAppAdvertisement**：看 IAA 视频得币（关联广告收入）  
- **ShareToReward**：分享得币（关联裂变 / K）

### 3.3 用户行为分型（分析视角）

| 类型 | 偏好示例 | BI 关注 |
|------|----------|---------|
| **博弈型** | Crash、Double Mines、Slot | RTP、下注频次、ARPU |
| **社交型** | 派对上麦、Bato-Bato、Tongits | 在线时长、上麦时长、送礼额（魅力值） |

## 四、BI 风控与熔断告警 (Risk Control & Alerting)

自动化 BI 建议配置 **实时监控 + Lark / 电话** 告警。

### 4.1 业务熔断类指标

- **全局 RTP**：理论 vs 实际偏差；异常「放水」时熔断并 **隔离可疑注单**。
- **单游戏 RTP**：如 Crash 水池、赔付率异动。
- **活动产出**：如大转盘 **人均金币产出**，防羊毛刷币。

### 4.2 黑名单与防刷

- **维度**：User_ID、Device_ID、Device_SN、IP_Address。
- **触点**：登录、进派对房、进游戏厅、充值、提现等。

## 五、数据异常协同 — 责任人映射 (Stakeholder Mapping)

自动化报告在命中特定异常时，可路由抄送对应负责人（与干系人表一致处可再校验拼写）。

| 异常类型 | 建议对接 |
|----------|----------|
| 经济模型、RTP 异常、BI 报表需求 | **Vigo, Mark**（数值/经济）、**Haku**（风控产品） |
| CAC 超标、eCPM 异常、TikTok 转化 | **Berlith (Berlin), Jovi**（市场/运营） |
| 注册/充值漏斗流失过高 | **Victor**（注册、钱包、充值） |
| 派对房活跃、语音使用异常 | **Blake**（语音厅、派对机制） |
| 任务参与、等级停滞 | **Bessie**（任务、等级、排行榜） |

## 六、BI 系统配置与埋点建议（摘要）

1. **优先看板**  
   - **买量投产比（ROI）追踪**  
   - **用户 120 秒注册 + 首充漏斗**

2. **事件埋点（强烈建议）**  
   - 破产保护：**触发次数** `TriggeredTimes`  
   - 对应 **挽留方式** `PromotionId`  
   - 用于评估保本策略对 **次日留存** 等的拉动。
