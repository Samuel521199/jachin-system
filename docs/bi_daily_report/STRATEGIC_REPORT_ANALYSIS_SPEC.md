## 冲 DAU 阶段 · 禁止 RTP 叙事（强制 · 全文）

即使输入 JSON/摘要里出现 **RTP、返币率、GGR、放水、通胀、调回 95%–98%** 等字段，**大战报正文一律不得展开**，包括但不限于：

- 禁止用 RTP/GGR 解释 DAU 涨跌、用户流失或「经济不健康」
- 禁止建议「下调 RTP」「止血」「薅羊毛」「金币通胀」「杀鸡取卵式放水」
- 禁止把某游戏 RTP>100% 当作核心风险或战略赌注的主因
- 禁止在第五节写「经济模型止血 / 下调 Tongits RTP」类选项

**允许替代的叙述角度**（用增长语言，不用控盘语言）：

- **局数 / 人均局数 / 进桌率 / 完成首局比例** → 代表「玩没玩起来」
- **注册→进桌→次日再开** → 代表漏斗与留存质量
- **买量渠道、DNU/设备、次留（见下「留存日历」）** → 代表流量质量
- **IAA 盲区** → 代表 ROI 能否评估（与 IAP 弱并列，仍须写）
- 高产出/高赠送金币若出现，只可说「用户拿币多、可能影响后续付费或广告承接」，**不得**上升到 RTP 调控建议

## 留存日历（强制 · 禁止误判）

留存表每行日期 = **当日新增用户 cohort**；「次日 T+1 留存」= 这些用户在 **下一个自然日** 是否回访。

| 情况 | 写法 |
|------|------|
| **数据日 T 当行** T+1 = 0 或 NaN% | **正常**，T+1 自然日尚未结束，**禁止**写 ETL 故障、留存崩盘、「无法验证今日新增」 |
| **T-1 及更早** 的 T+1 % | **真实次留**，分析必须引用（如昨日 11.38%） |
| 评价「今日 DNU 质量」 | 写「次留待明日 T+1 数据落地后验证」；可对比昨日次留与近 7 日趋势 |

**禁止**：因 T 日次留=0 在 🔍【待验证】里列「次留 ETL 待修复」（除非 T-2 及更早行也长期为 0，那才是真异常）。
