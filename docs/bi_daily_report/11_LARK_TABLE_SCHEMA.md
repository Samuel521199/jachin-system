# Lark 多维表格字段结构规范

BI 战报同步到 Lark 多维表格时，各子表需按此文档创建对应字段。字段名需与 CSV 列名**完全一致**，否则会触发 `FieldNameNotFound` 等错误。

> 参考实现：`l3_node/skills/bi/bi_daily_report/main_skill.py`  
> 配置映射：`config/skills/com.jachin.bi.daily_report/bi_daily_report.yaml` 的 `lark_bitable.tables`  
> 业务规则与数据来源：`BI分析对应lark表格的规则.txt`（与 BI 后台菜单路径一致）

---

## 一、用户登录活跃情况

### 1. DAU和DNU（增幅 + 数值）

**数据来源**：日日活统计（`stats_user_dau`）与日日新用户统计（`stats_user_new`）汇总行；增幅 = 最新日相对前一日。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `类型` | 文本 | 取值：`DAU`、`DNU` |
| `增幅（%）` | 数字 | 较前一日变化，如 `-9.73` 表示 -9.73% |
| `数值` | 数字 | 最新统计日的 DAU 或 DNU 绝对量 |

**对应 CSV**：`01_用户活跃_增幅表.csv`

---

### 2. 周统计DAU和DNU数量（日期数量表）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `日期` | 日期 | **YYYY-MM-DD**（提纯 CSV 输出；同步时按 Lark 日期类型写入） |
| `DAU数量` | 数字 | 日活用户数 |
| `DNU数量` | 数字 | 当日新增用户数 |
| `老用户数量` | 数字 | `DAU数量 - DNU数量`（同日汇总口径） |

**对应 CSV**：`02_用户活跃_日期数量表.csv`

---

### 3. DAU渠道来源

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `DAU渠道来源` | 文本 | 渠道名称 |
| `数量` | 数字 | 该渠道日活用户数 |

**对应 CSV**：`03a_用户活跃_DAU渠道来源.csv`

---

### 4. DNU渠道来源

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `DNU渠道来源` | 文本 | 渠道名称 |
| `数量` | 数字 | 该渠道新增用户数 |

提纯 CSV **仅含上列两字段**，与常见 Lark 子表结构一致。若需在多维表中展示「老用户数量」，请在 Lark 侧用公式列（由 DAU 渠道表关联计算），勿强制同步第三列以免 `FieldNameNotFound`。

**对应 CSV**：`03b_用户活跃_DNU渠道来源.csv`

---

### 5. 日活占比（固定两行）

**数据来源**：日日活统计 + 日日新用户统计汇总行；最新日 `DNU` → 新用户行，`DAU - DNU` → 老用户行。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `用户` | 文本 | 固定两行：第一行 `新用户`，第二行 `老用户` |
| `日活` | 数字 | 该行对应的日活人数（非占比小数，与 Lark 表一致） |

**对应 CSV**：`12_用户活跃_日活占比.csv`

---

### 6. 新增设备数

**数据来源**：日日新用户统计（`stats_user_new`）汇总行；增幅 = 最新日新设备数相对前一日。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `日期` | 日期 | 数据日；CSV 中为 **YYYY-MM-DD** 字符串（同步层会按 Lark 日期类型写入） |
| `新增设备数量` | 数字 | 当日新增设备数 |
| `新增设备增幅（%）` | 数字 | 较前一日增幅（百分点）；CSV 列名须与多维表字段名一致，避免 ensure_columns 另建「涨幅」列 |
| `新增用户/新增设备` | 数字或文本 | DNU÷新增设备数，无设备时可为 `-` |

**对应 CSV**：`13_用户活跃_新增设备表.csv`

## 三、平台消耗情况

### 11. 当日金币产出、消耗（全）

**数据来源**：平台产销情况（`prod_sales`）全部汇总行 + 日新用户统计（`stats_user_new`）汇总行的「当日新增用户产出/消耗」；旧用户 = 全部 − 新用户。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `日期` | 日期 | 毫秒时间戳 |
| `全部产出` | 数字 | 用户金币产出总数 |
| `全部消耗` | 数字 | 用户金币消耗总数 |
| `新用户金币产出` | 数字 | 当日新增用户产出 |
| `新用户金币消耗` | 数字 | 当日新增用户消耗 |
| `旧用户金币产出` | 数字 | 全部产出 − 新用户金币产出 |
| `旧用户金币消耗` | 数字 | 全部消耗 − 新用户金币消耗 |

**对应 CSV**：`08_消耗_每日表.csv`

---

### 11b. 当日金币产出、消耗（渠道层）

**数据来源**：**BI 平台管理 → 数据统计分析 → 用户数据统计 → 日活统计**（`stats_user_dau`）。取**最新数据日**（与战报 `t1` 一致则优先，否则取 raw/表内最新日）下、**各渠道明细行**；排除「全部汇总」「> ALL」等汇总行。

**说明**：多维表子表通常**不建「日期」列**（数据日与当次战报同步批次一致）；CSV 与 Lark 均为 **三列**。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `渠道` | 文本 | 与 BI「渠道」一致（如 meta_ads06、unknown） |
| `金币产出` | 数字 | BI 渠道行「**当日金币产出**」 |
| `金币消耗` | 数字 | BI 渠道行「**当日金币消耗**」或「**当日今日消耗**」（列名因导出略有差异，提纯会匹配） |

**对应 CSV**：`08b_消耗_金币_渠道层.csv` — 表头：`渠道`, `金币产出`, `金币消耗`

---

### 12. 每个游戏的产出、消耗

**数据来源**：平台产销情况（`prod_sales`），最新日按游戏（统计范围）展开。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `游戏名称` | 文本 | 统计范围（游戏名） |
| `产出` | 数字 | 用户金币产出 |
| `消耗` | 数字 | 用户金币消耗 |

**对应 CSV**：`09_消耗_按游戏表.csv`

---

### 13. 付费人数表格（不同充值金人数）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `不同充值金额分等级` | 文本 | 档位，如 `(0, 50]` |
| `人数` | 数字 | 该档位付费人数（充值次数） |

**对应 CSV**：`10_充值_付费人数按SKU.csv`

---

### 14. 付费人数表格（不同充值金金额）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `不同充值金额分等级` | 文本 | 与人数表档位一致 |
| `此等级总金额` | 数字 | 该档位金额合计 |
| `付费金额增幅（%）` | 数字 | **整表口径**：最新日各档「此等级总金额」之和，相对前一日的总付费增幅（每行填同一数值即可） |

**对应 CSV**：`11_充值_付费金额按SKU.csv`

---

### 15. 付费人数、金额、增幅（单行汇总表，若多维表中仍保留）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `当天付费人数` | 数字 | 当日付费用户数 |
| `付费总金额` | 数字 | 当日充值总金额 |
| `增幅` | 数字 | 付费总金额较前一日增幅（%） |

**对应 CSV**：`14_充值_付费人数金额增幅表.csv`

---

### 16. Arpu（多维表名建议「Arpu」，勿拼成 Arup）

**数据来源**：**BI 平台管理 → 平台数据 → 日常报表 → 每日运营数据汇总**（`daily_ops_summary`）。取**最新完整数据日**（优先战报 `t1`）的 **Arpu** 列，**增幅（%）** = 相对前一日的环比。若无日运营表，可回退充值统计中的 Arpu 列。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `日期` | 日期 | **YYYY-MM-DD** |
| `Arpu数值` | 数字 | 与 BI 表头「Arpu」一致 |
| `Arpu增幅（%）` | 数字 | 较前一日变化（百分点）；**勿用「涨幅」**以免与旧拼写 Arup 混用导致多维表多建列 |

**对应 CSV**：`15_消耗_Arup表.csv`（文件名保留历史 slug；列为 **Arpu增幅（%）**）

---

### 17. Arppu

**数据来源**：同上 `daily_ops_summary` 的 **Arppu** 列；**增幅（%）** = 相对前一日。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `日期` | 日期 | **YYYY-MM-DD** |
| `Arppu数值` | 数字 | 与 BI「Arppu」一致 |
| `增幅（%）` | 数字 | 较前一日变化（百分点）；与常见 Lark 字段名一致，勿另建「涨幅（%）」 |

**对应 CSV**：`16_消耗_Arppu表.csv`

### 22. 游戏深度参与情况

**数据来源**：**BI 平台管理 → 数据统计分析 → 游戏数据统计 → 核心产品每日数据表**（raw / DuckDB：`stats_game_core`）。取 **数据日 t1**（与战报一致）下 **`游戏名称` 与下列两款完全一致** 的行：

1. `Tongits King`  
2. `Color Blitz Social`

**口径说明**：

- 全平台列：与源表「全体用户」口径一致——`进入游戏房间用户数`、`真实进房总人数`、`完成游戏用户数` 直接取同源列。
- **「3局 / 6局通过人数（全平台）」**：取 `新用户3局通过人数/通过率`、`老用户3局通过人数/通过率`（及 6 局对应列）中 **斜杠前的人数**，**全平台 3 局 = 新用户 3 局人数 + 老用户 3 局人数**，**全平台 6 局 = 新用户 6 局人数 + 老用户 6 局人数**。
- **「新用户*k*局通过人数（新用户）」**：自 `新用户k局通过人数/通过率` 解析 **人数**（忽略通过率）；**老用户 3/6 局** 同理。

- 若多维表字段名使用半角括号 ` (全平台) ` 等与下表不一致，请在 `bi_daily_report.yaml` 的 `field_mapping` 中为 `20_游戏_游戏深度参与情况.csv` 配置列映射。

## 六、常见错误与处理

| 错误类型 | 原因 | 处理 |
|----------|------|------|
| FieldNameNotFound | 字段名与 CSV 列名不一致 | 1）`ensure_columns: true`；2）按本文档建列；3）`field_mapping` |
| DatetimeFieldConvFail | 日期列用了文本 | Lark **日期**类型 + 毫秒时间戳 |
| TextFieldConvFail | 纯数字档位被误转为 float | `text_columns` 覆盖「不同充值金额分等级」等 |
