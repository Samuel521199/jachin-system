# Lark 多维表格字段结构规范

BI 战报同步到 Lark 多维表格时，各子表需按此文档创建对应字段。字段名需与 CSV 列名**完全一致**，否则会触发 `FieldNameNotFound` 等错误。

> 参考实现：`l3_node/mcp_tools/bi/report_refiner.py`  
> 配置映射：`config/skills/com.jachin.bi.daily_report/bi_daily_report.yaml` 的 `lark_bitable.tables`

---

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `类型` | 文本 | 取值：DAU、DNU |

## 二、平台留存情况

### 5. 次留表

**逻辑说明**：`类型` 列为固定值（Lark 中预建三行），同步时按类型匹配并填入 `数字`、`百分比` 即可。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `类型` | 文本 | **固定三行**，仅匹配不写入；见下 |
| `数字` | 数字 | 人数，需填入 |
| `百分比` | 数字 | 小数，如 0.45 表示 45%，需填入 |

**类型的三个固定值**：

1. `T-2次留（前填注册的人当中昨天又登录了的人）`
2. `1-4三留（4天前注册的用户，在第3天是否活跃）`
3. `T-8七留（统计 8 天前注册的用户，在第 7 天是否活跃）`

**对应 CSV**：`04_留存_次留表.csv`  
**Lark table_id**：tblieBOTmvhzqVFG

> 若 report_refiner 输出的类型与上述固定值不一致，需在 `report_refiner.py` 中增加类型映射逻辑。

## 六、常见错误与处理

| 错误类型 | 原因 | 处理 |
|----------|------|------|
| FieldNameNotFound | 字段名与 CSV 列名不一致 | 按本文档建列，列名完全一致 |
| DatetimeFieldConvFail | 日期列用了文本或格式不对 | 使用 Lark **日期** 类型，同步值为毫秒时间戳 |
| TextFieldConvFail | 纯数字 SKU 被误转为 float | `不同充值金额分等级` 用**文本**类型；refiner 会对纯数字加零宽字符 |
