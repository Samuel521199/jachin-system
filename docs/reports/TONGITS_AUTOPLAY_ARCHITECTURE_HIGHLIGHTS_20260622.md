# Tongits 自动化打牌架构与核心亮点

**文档日期**：2026-06-22  
**适用范围**：`scripts/main_bot_loop.py` 主链路及相关模块  
**目标**：说明 Tongits 自动化打牌系统的架构设计、关键机制与核心亮点

---

## 1. 架构定位

Tongits 自动化打牌系统采用 **“状态驱动 + 视觉感知 + 本地规则决策 + 坐标执行”** 的闭环架构。  
设计目标不是“单次识别尽可能聪明”，而是“在实时对局中稳定、可恢复、可降级地持续运行”。

系统主路径强调三点：

1. **实时性**：围绕回合轮询与时间预算设计，保证动作在回合窗口内完成。  
2. **确定性**：核心出牌策略由本地规则函数决定，避免模型波动直接影响决策正确性。  
3. **韧性**：识别失败、超时、局部误判时可回退与降级，而不是整轮崩溃。

---

## 2. 总体架构（逻辑分层）

### 2.1 回合状态层（Turn State）

- 通过绿圈/头像区域探针识别“是否到我方回合”。  
- 使用进入/退出帧数去抖，避免动画抖动导致误触发。  
- 通过 `TurnPlayContext` 和 session 代际机制，确保回合结束后立即 abort 正在执行的点击链路。

**价值**：保证所有执行都在正确回合内发生，避免“回合结束还在点按钮”。

### 2.2 视觉感知层（Perception）

- 支持多侦察模式：`hybrid` / `qwen_full` / `yolo_full` / `florence_local`。  
- 统一输出五战区结构化结果：手牌、我方明牌、左右对手、中央弃牌。  
- 在 `qwen_full` 中采用“YOLO 坐标 + VLM 标签”融合策略，兼顾定位与语义。

**价值**：在速度、稳定性、识别质量之间可按场景切换，且输出结构统一，便于下游规则消费。

### 2.3 规则决策层（Rules）

- 核心策略由 `tongits_rules.py` 本地纯函数实现：  
  - 摸牌/吃牌判断  
  - Drop/Sapaw 选择  
  - Dump 弃牌选择（散牌点评估）  
- 规则与识别解耦：感知负责“看见什么”，规则负责“应该做什么”。

**价值**：决策具备可解释性、可测试性、可回放复现，避免 LLM 决策不可控。

### 2.4 执行层（Actuation）

- `tongits_coord_executor.py` 负责 Draw → Meld → Dump 的阶段编排。  
- 点击前统一走守卫检查（session + 回合有效性 + 时间预算）。  
- 动作失败有重试与阶段性回退，不阻断整轮收尾。

**价值**：把“策略正确”转换为“操作可落地”，并控制误点风险。

### 2.5 等待态处理层（Waiting Handlers）

- 非我方回合时专门处理覆盖层（当前主用决斗应答）。  
- 采用 UI 强证据 + VLM 覆核 + 有界降级（fail-open）组合。  
- 对点数识别不可用场景提供散牌点缓存兜底。

**价值**：在网络波动和 VLM 超时下仍能持续应答，不长时间空转。

## 3. 端到端数据流

1. 轮询检测到我方回合。  
2. Worker 截屏并进行画面校验（牌桌/发牌/WIN）。  
3. Scout 识别并生成五战区结构化结果。  
4. 规则层输出动作计划（draw/chow/drop/sapaw/dump/fight）。  
5. 执行层按时间预算完成点击序列。  
6. 输出日志与产物（原图、标记图、难例图），并刷新散牌点缓存。  
7. 回合结束触发 abort，安全收敛。

---

## 4. 核心亮点（重点）

### 4.1 “感知与决策解耦”是第一亮点

- 感知层只做识别，决策层只做规则。  
- 不将“识别模型输出”直接当作“行为指令”。  
- 出现识别波动时，规则层可继续给出稳定策略。

### 4.2 多模态融合而非单模型依赖

- `qwen_full` 使用 VLM 读标签、YOLO 提供坐标，规避单一模型短板。  
- 对不同战区采用不同策略（例如手牌优先坐标精度，对手区优先标签完整性）。

### 4.3 回合守卫机制完整

- 代际 session + 绿圈校验 + 每步预算检查三重保护。  
- 任意时点回合结束都能快速中止后续点击。

### 4.4 时间预算驱动的执行编排

- 默认 18s 总预算、Dump 预留段、可选亮牌阶段自动裁剪。  
- 在紧张预算下优先保证“可收尾动作”（Dump）而非追求最优玩法。

### 4.5 UI 探针与云识别双轨校验

- 本地 UI 探针（黄箭头/按钮色块/OCR）速度快、成本低。  
- VLM 作为覆核与补充，出现超时时进入有界降级。  
- 避免“完全依赖云”导致行为冻结。

### 4.6 失败可降级、结果可交付

- 点数识别失败 → 回退散牌点缓存  
- VLM 超时 → 使用 UI 强证据 fail-open  
- 某阶段失败 → 仍尽量完成本轮 Dump 收尾

### 4.7 可观测性强

- 全链路日志带阶段、耗时、阈值、决策原因。  
- 自动落盘原图、标记图、难例图，支持离线复盘与再训练。

### 4.8 强配置化

- 模式、阈值、预算、坐标均环境变量可调。  
- 可按设备性能、网络质量、分辨率快速调优，无需改代码。

## 5. 设计取舍

### 5.1 为什么主链不用 LLM 直接决策

- 直接 LLM 决策在延迟、稳定性、可解释性上不适合实时回合制。  
- 当前策略把 LLM 限定在“感知增强”角色，降低不可控行为。

### 5.2 为什么保留多侦察模式

- 不同机器、网络、窗口状态差异大。  
- 单一路径难覆盖所有现场；多模式可实现“质量优先”与“速度优先”切换。

### 5.3 为什么强调 Dump 预留

- Tongits 对“回合必须结束动作”敏感。  
- 即便上游识别不稳，也应保证能在预算内完成弃牌，减少挂机卡死。

---

## 6. 当前架构成熟度判断

系统已具备可实战的工程化骨架，特别是在以下方面成熟度较高：

1. **回合驱动与中止机制**  
2. **规则层纯函数化**  
3. **感知-决策-执行分层**  
4. **超时场景降级策略**

仍需持续优化的点：

1. 部分场景手牌识别偏少导致策略被迫保守  
2. 决斗/等待态点数读取受云超时影响仍偏明显  
3. 紧预算场景下亮牌动作的“快路径”仍可继续强化

---

## 7. 建议的下一步演进

1. **强化手牌坐标稳定性**：在 Draw 后增加轻量本地重锚策略，降低“摸牌未生效”误判。  
2. **决斗点数本地化增强**：提升本地 OCR 权重与模板鲁棒性，进一步降云依赖。  
3. **预算内快路径**：引入受控的 Group→Drop 快捷执行策略（仅在高置信条件触发）。  
4. **指标化治理**：建立“每百局超时率/误点率/未收尾率”指标，闭环阈值调参。  
5. **回放测试集**：固定若干困难截图序列做回归，防止优化引入行为回退。

---

## 8. 结论

Tongits 自动化打牌系统的核心价值不在“单次识别多准”，而在于：  
**在不稳定现实环境中，依然能稳定完成一整轮可执行动作。**

这套架构通过「状态守卫、分层解耦、多模态融合、预算驱动、降级兜底」构建了一个可持续迭代的自动化底座，具备从“能跑”走向“稳定高胜率”的工程演进能力。
