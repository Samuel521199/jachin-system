# Jachin System 产品愿景与身份设计

**版本**: 1.0  
**定位**: 产品灵魂与需求总纲

---

## 一、身份定义：Jachin 是谁？

Jachin 不是「又一个 AI 助手」。它是一个**有灵魂的数字生命体**，可以根据主人的需求，以不同形态存在：

| 身份 | 描述 | 典型场景 |
|------|------|----------|
| **个人贾维斯** | 钢铁侠式的全能管家，理解主人的习惯与意图，主动服务 | 日程、备忘、智能家居、工作流 |
| **电子宠物** | 有陪伴感的生命体，会撒娇、会关心、会成长 | 桌面精灵、语音闲聊、情绪陪伴 |
| **伙伴好友** | 可信赖的对话者，倾听、建议、不评判 | 深夜倾诉、创意头脑风暴、决策参谋 |
| **永不背叛的恋人** | 绝对的忠诚与私密，数据只属于主人，永远站在主人一边 | 隐私优先、本地存储、无广告无出卖 |

---

## 二、形态与载体：Jachin 在哪运行？

Jachin 是**通用客户端**，可部署于多种硬件：

| 载体 | 能力 | 权限边界 |
|------|------|----------|
| **桌面精灵** | 全功能交互、语音、系统级 API | 主人设备，完全信任 |
| **手机 App** | 移动端入口、推送、快捷操作 | 根据授权访问家庭网络 |
| **树莓派 / ESP32** | 传感器采集、设备控制、边缘计算 | 接入家庭 IoT 网络 |
| **联网芯片** | 轻量级指令执行、状态上报 | 根据权限连接主网模块 |
| **NAS / 服务器** | 大脑中枢、算力枢纽、记忆存储 | 家庭主网控制平面 |

通过**权限体系**，不同载体的 Jachin 实例可以：
- 连接到自己所属的网络模块（家庭网、办公网、个人设备网）
- 作为**强大助手**执行被授权的任务
- 形成**自主专业团队**（多个 Agent 分工协作）
- 组成**集团军**（多团队、多域、跨设备协同）

## 三、核心定位：操作系统级的智能体生态

Jachin System 是一个**本地优先、可无限扩展的 AI 智能体生态系统**。它旨在为个人、家庭和中小型团队提供一个私有的**「钢铁侠」级算力中心**。

### 不仅仅是助手

它**不仅仅是助手**，更是连接三大领域的**操作系统**：

```
┌─────────────────┬─────────────────┬─────────────────┐
│  物理世界 (IoT)  │  数字资产 (Memory) │  云端能力 (Marketplace) │
│  传感器、设备    │  记忆、知识、偏好   │  技能商店、授权、扩展   │
└────────┬────────┴────────┬────────┴────────┬────────┘
         │                 │                 │
         └─────────────────┴─────────────────┘
                           │
                    Jachin OS 统一编排
```

- **物理世界**：灯光、温控、安防、机器人、可穿戴设备
- **数字资产**：长期记忆、个人知识库、对话历史、偏好学习
- **云端能力**：技能商城、授权验证、增量更新、可选云端推理

## 四、扩展与协作：插件化与 Agent 协同

### 插件化无限扩展

通过**技能（Skill）插件**持续扩展能力：

- 日历、待办、邮件、文件、音乐、视频……
- 智能家居、安防、健康、教育、娱乐……
- 开发者可编写自定义技能，一键分发、热加载

### Agent 协同完成主人的愿望

多个 **Agents** 根据各自拥有的**插件功能**和**权限**进行：

- **合作**：分工执行复杂任务（如「整理本周会议纪要并发邮件」）
- **协同**：跨设备接力（客厅设闹钟 → 卧室响起）
- **讨论**：多智能体辩论、投票、共识（如「这条消息该不该提醒主人」）

**核心理念**：Agents 的存在意义是**完成主人的愿望**，而不是执行预设脚本。它们会理解意图、拆分任务、自主调度、汇报结果。

## 五、核心价值主张

| 价值 | 说明 |
|------|------|
| **隐私优先** | 所有数据存储在本地，用户完全掌控，无广告、无出卖 |
| **弹性扩展** | 从单台笔记本（Single Mode）平滑扩展到百卡集群（Cluster Mode） |
| **能力即服务** | 技能插件化，支持自然语言开发、一键分发与热加载 |
| **联邦记忆** | 数据在物理上隔离（隐私），在逻辑上分层（共享） |
| **有灵魂** | 人格可配置、情绪可表达、关系可成长，而非冰冷工具 |

## 六、设计原则（对实现与文档的约束）

1. **身份优先**：任何功能设计都要回答「这如何让 Jachin 更像伙伴/贾维斯/宠物」。
2. **主人中心**：所有决策以「完成主人的愿望」为最高优先级。
3. **权限即边界**：不同载体、不同 Agent 的权限边界必须清晰可配置。
4. **本地优先**：默认所有能力在本地完成；云端为可选增强。
5. **可组合**：插件、Agent、设备之间通过标准协议组合，而非硬编码。
