## 1. 模型

| 概念 | 说明 |
|------|------|
| **前台** | 用户主会话 `run_agent`：同线程内 ReAct；默认对非豁免工具施加 **同步超时**（见 §4）。 |
| **后台** | `core:submit_background_task`：**SQLite `insert_pending`（WAL）** 与 **`asyncio.Queue.put_nowait` 双写**，由 **N 个 Worker** `await run_agent`；与前台 **并发**。 |
| **背压** | 队列 `maxsize` 满时 `put_nowait` 失败 → `delete_pending` + 返回 JSON `status=rejected` + `reason=resource_exhausted`（不抛异常）。话术上勿承诺「自动路由 L2」；仅说明稍后再试或缩小任务。 |
| **崩溃对账** | 启动时 **`reconcile_stale_background_tasks_on_startup`**：磁盘上 `running`/`queued` → **`interrupted`**。另 **`_recover_sqlite_pending_queue`** 将 SQLite 中仍为 pending 的行灌回内存队列（与 JSON 终端状态对账）。 |
| **优雅停机** | `graceful_shutdown` 钩子 → **`flush_background_tasks_to_persistent_queue`**（内存队列中尚未被取走的 job 写回 SQLite）+ Worker 取消 + running 标 **`interrupted`**。 |
| **任务时间线** | **`~/.jachin/workspace/.background_tasks/tasks_index.jsonl`**：queued/started/completed 等 append-only 行（供观测或 CLI/UI）。 |
| **事件** | `l3_node/l3_event_bus.py`：WebSocket 客户端发送 `subscribe_background_tasks` 后可收 `type: background_task`。 |

工具 ID（白名单内）：**`core:submit_background_task`**、**`core:check_background_task`**（勿与文档口语 `submit_background_task` 混淆）。

- 环境变量 **`JACHIN_BACKGROUND_TASKS=0`**：禁止投递后台任务（仍可 `check` 历史）。

## 4. 前台同步超时与预取

- **超时**：`foreground_tools.enabled` 且 `sync_timeout_sec > 0` 时，对未豁免工具使用 `asyncio.wait_for`（MCP 直接 await；Native 用 `asyncio.to_thread(run_tool)`）。超时 Observation 为 JSON，提示长任务走 **`core:submit_background_task`**。  
- **线程 / 协程「幻觉」**：`wait_for` 超时后 **不会** 终止 `to_thread` 或 MCP 内部已发起的同步阻塞调用（如卡死的网络读）。Python 层无通用「杀线程」；缓解方向：易阻塞能力用 **子进程 + 超时 kill**、或 **取消令牌** 协作退出；默认线程池有并发上限，但大量卡死仍会占满池子。日志会打 `[L3 Agent] 前台工具超时 … 仍可能继续`。  
- **豁免（元数据优先）**：MCP 工具在注册 dict 上声明 **`long_running: true`**，或 **`jachin.long_running`** / MCP **`annotations.longRunning`**（由 `mcp_registry.tool_entry_long_running` 识别）。另可在 `foreground_tools.long_running_tool_ids` 写全量工具 ID。**默认不再**用 `allow_substrings` 做宽泛匹配（避免 `mcp:atom_*` 误豁免）；若需兼容旧行为，仅在 `nexus_config` 中 **显式** 配置 `allow_substrings`。  
- **预取**：工具返回后，按用户意图关键词在 **`~/.jachin/workspace` 下 `*.md`** 取少量摘录，拼在 Observation 后（标记 **`【relevant_context_prefetch】`**）。**`ctx.metadata`** 维护 **`_prefetch_paths_shown`（滑窗）**、`_prefetch_session_bytes`、**`_react_iteration`** 与 **`_context_path_ledger`**；**`core:fs_read` / `mcp:read_file`** 路径统一登记。同一次 `run_agent` 内大块 Observation 可经 **`observation_dedup`** 折叠。后台通道 **`background_task`** 不预取。

## 4.1 后台 `progress.md` 写入

多个 Worker 并发完成/失败时，经 **`asyncio.Lock` + `to_thread`** 串行追加 **`workspace/progress.md`**，避免多协程同时 `open(..., "a")` 导致行级交织。
