## 五、后续计划：长任务与「读/等」不阻塞主界面（7 项）

**总结项（本节总览）**：大附件与 WS/多模态在后台或线程池处理，主界面与 asyncio 事件环不因读文件、解析 JSON 或通义快照名而卡顿或误配。

1. **总结项**：附件 Base64 与 metadata 组装下沉 Web Worker，主线程不掉帧。
   - [ ] `clients/desktop/src/workers/attachment.worker.ts` + `clients/desktop/src/utils/attachmentPayloadCore.ts` — 附件「读文件 → Base64 → 组装 `attachments_metadata`」在 Worker 内完成。

2. **总结项**：主线程仅通过 Promise 调 Worker，对外 API 不变。
   - [ ] `clients/desktop/src/utils/attachmentPayload.ts` — Promise 封装 Worker；发往 L3 的结构与现网一致。

3. **总结项**：有附件发送前给出明确 loading，避免「点了没反应」。
   - [ ] `clients/desktop/src/chat.tsx` — 编码进通道前进入 loading / thinking。

4. **总结项**：Omni 流式中心跳与正文分离，展示层收敛。
   - [ ] `clients/desktop/src/utils/reasoningStreamSplit.ts` + `clients/desktop/src/components/Omni/JachinOmniCyberProtocol.tsx` — 心跳 / trace 与主文拆分。

5. **总结项**：超大 WS JSON 解析迁出事件循环，防整节点假死。
   - [ ] `l3_node/ws_server.py` — 大帧 `json.loads` 使用线程池（或等效）避免阻塞 asyncio。

6. **总结项**：多模态附件抽取前加硬预算，防无界遍历与 OOM。
   - [ ] `l3_node/intent_gateway/multimodal_attachments.py` — xlsx / docx / PDF / txt·md·csv·log 等字节/字符/页数上限在进入模型前生效。

7. **总结项**：通义快照后缀剥离与单测，复杂档走稳定模型 id。
   - [ ] `core/llm_provider.py` + `tests/unit/test_llm_qwen_snapshot_normalization.py` — 去掉 `-YYYY-MM-DD` 快照尾缀；复杂档默认 `dashscope/qwen3-max` 等稳定 id。
