## 3. 数据表结构（字段级）

下列四张表为 **PMO 仪表盘推送** 与本地 CSV 一一对应关系（CSV 文件名见 `~/.jachin/client_volumes/PMO/output/` 或技能内常量）。

### 3.1 需求完成情况

| 属性 | 值 |
| --- | --- |
| 表名（界面） | 需求完成情况 |
| `table_id` | `tblUjVGoTEbqxFeu` |
| 本地 CSV 文件名 | `PMO_需求完成情况.csv` |

| 字段名（须与飞书一致） | 类型（界面） | 说明 |
| --- | --- | --- |
| 需求内容 | 文本（主字段，带锁图标） | 与提纯 CSV 列名一致；取值来自 raw ``req_march_coarse`` 的 **「需求内容」**（无则回退「需求简述」） |
| 需求类型 | 文本 | 来自 **「需求类型」**；表中空行在业务上继承上一行类型，提纯时采用**上一非空类型**填充 |
| 开始时间 | 日期或文本 | 取该需求行在 **「分析、调研报告」～「生产发布」** 各列中**最早**日期，格式化为 `YYYY-MM-DD`；若该范围内**无任何有效日期**，填 **「空」**（同步时若日期列不接受，可改为文本列或字段映射） |
| 结束时间 | 日期或文本 | 仅看 **「生产发布」** 列；有日期则 `YYYY-MM-DD`；**无则填「未完成」** |
| 当前完成度 (%) | 数字 | **优先**从仓库 ``docs/pmo_bmo_plugin/output/PMO_大需求对齐_{日期}.md``（或 ``PMO_大需求对齐.md``）对应需求章节解析 **「约 xx%」**；若无则按管线列已填节点数 / 7（见上「开始时间」所列七列）估算百分比 |
| 完成到哪一步了 | 文本 | **优先**从同上对齐报告解析 **「推断阶段」**；若无则取管线中**最后一个已填日期的阶段列名**（如「需求评审」）；皆无则 **「未进入主线」** |

> 提纯实现：`l3_node.skills.pmo_bmo.main_skill.write_pmo_dashboard_csvs`。流程语义见 ``04_PROCESS_FLOW_AND_OUTPUT_SPEC.md``。

### 3.3 需求人员参与情况

| 属性 | 值 |
| --- | --- |
| 表名（界面） | 需求人员参与情况 |
| `table_id` | `tblGWpIj6Gif1znE` |
| 本地 CSV 文件名 | `PMO_需求人员参与情况.csv` |

| 字段名（模式） | 类型（界面） | 说明 |
| --- | --- | --- |
| 需求内容 | 文本（主字段，带锁） | 与 raw ``req_march_coarse`` 的 **「需求内容」** 一致（无则回退「需求简述」） |
| 需求类型 | 文本 | 来自 **「需求类型」**；空行继承上一行非空类型 |
| 人员1 … 人员*n* | 文本 | 动态列：人数由该需求在明细中的执行人数量决定，**最多**与技能常量 `PMO_REQ_PARTICIPATION_MAX_PAIR_COLS`（40）对一致 |
| 完成度1 … 完成度*n* | 数字 | 与 **人员*k* 成对**；数值来自 ``docs/pmo_bmo_plugin/output/PMO_需求人员参与明细.md`` 各 ``#### 开发/美术 · 姓名`` 小节中的 **平均完成度（估算）**（去掉 `%` 写入 CSV；无法推断时为 **「—」→ 空单元格**） |

**提纯逻辑**（`write_pmo_dashboard_csvs`）：

1. 按 `req_march_coarse` 每条需求一行输出 **需求内容 / 需求类型**。
2. 解析 ``output/PMO_需求人员参与明细.md``（或 `PMO_需求人员参与明细_{日期}.md`）中与大需求标题（`## 标题`）对齐的小节，按出现顺序收集「开发/美术 · 姓名」及对应平均完成度。
3. CSV 列宽 = 全局最大参与人数（本批需求中的最大值），列名为 `人员1`、`完成度1`、`人员2`、`完成度2` … 依次成对扩展；不足列填空。

> 同步提示：首次增加「需求类型」或更多 `人员n/完成度n` 列时，建议在 `pmo_dashboard_push` 中开启 **`ensure_columns: true`**，以便自动建列。CSV 表头须与多维表字段名一致；若仍报 `FieldNameNotFound`，使用 `field_mapping`。
