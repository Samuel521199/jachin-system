# 无感安全与渐进式授权 — UX 设计规范

**版本**: 1.0  
**状态**: 设计规范  
**定位**: 安全与易用性的统一 — 把最硬核的密码学藏在最极简的 UI 之下

---

## 核心哲学

> **安全与易用性往往是天敌，但真正划时代的产品，就是把最硬核的密码学死死地藏在最极简的交互之下。**

若让 Layer 2/3 用户手动复制 Ed25519 公钥、理解 SHA-256，神经元生态就只能是极客玩具，无法走向大众。

**设计原则**：把复杂留给系统，把简单留给用户。所有密码学校验在水下静默运行，**只有当检测到篡改时**才弹出警告。

---

## 一、设备的傻瓜式绑定 (Zero-Config Pairing)

**目标**：用户绝不接触「公钥/私钥」等词汇。采用 **Device Authorization Grant**（OAuth 2.0 RFC 8628），类似 Apple TV、智能电视、IoT 网关的绑定体验。

**详细协议**：详见 [PAIRING_PROTOCOL_SPEC.md](./PAIRING_PROTOCOL_SPEC.md)。

### 1.1 端云三次握手（用户仅参与第 2 阶段）

| 阶段 | 用户所见 | 背后发生 |
|------|----------|----------|
| **1. 机甲请求** | Layer 2 终端打印 `👉 J8K2X9 👈`，提示访问 `nexus.jachin/pair` | `POST /api/v1/pairing/request` → 云端生成 6 位码 + session_id（5 分钟有效） |
| **2. 指挥官授权** | 用户在 Console 输入 `J8K2X9`，点击「授权绑定」 | `POST /api/v1/pairing/confirm` → 绑定 user_id，注册 layer2_instances |
| **3. 密钥下发** | 机甲终端显示 `✅ 授权成功，机甲已连接至指挥部` | Layer 2 轮询 `GET /api/v1/pairing/status` → 拿到 access_token + layer1_public_key，写入本地 |

**用户操作**：仅输入 6 个字符。

### 1.2 安全防线

- **短生命周期**：6 位码 5 分钟失效
- **防暴破限流**：同一 IP 连续输错 5 次 → 封禁 1 小时
- **一次性消费**：拿到 Token 后 session 立即作废，防重放

## 二、权限的「大白话」翻译与一键授权 (Auto-Permissions)

**目标**：点击「部署到我的机甲」时，不弹出密密麻麻的 JSON Manifest。

### 2.1 系统自动翻译

云端解析 .jmp，将底层权限翻译成大白话：

| 底层权限 | 大白话 |
|----------|--------|
| `permissions.network: ["api.github.com"]` | 访问外部网络（仅限 github.com） |
| `permissions.filesystem: ["/tmp/plugin_a"]` | 读写临时目录 |
| `file.read`（未授权） | 读取本地文件（系统已自动禁用） |

### 2.2 类似 iOS 的弹窗体验

界面上只弹出一个**极简玻璃拟态卡片**：

```
┌─────────────────────────────────────────────────────┐
│  🛡️ 权限安全提示                                     │
│                                                      │
│  这款「GitHub 代码助手」需要以下权限，                │
│  系统已为您匹配最安全的推荐设置：                     │
│                                                      │
│  ✅ 访问外部网络（仅限 github.com）                   │
│  ❌ 读取本地文件（系统已自动禁用）                    │
│                                                      │
│  [ 一键安全安装 ]                                    │
└─────────────────────────────────────────────────────┘
```

### 2.3 背后发生的硬核操作

点击「一键安全安装」后：

- Layer 1 生成包含**用户授权状态**的最终部署指令
- Layer 2 拉取后，**严格按照该配置**初始化 WASM 沙箱（仅注入用户同意的权限）

## 三、云端无感打包 (Serverless Auto-Packaging)

**目标**：The Forge 中拼装完工作流后，无需在本地跑复杂 CLI 编译命令。

### 3.1 极简流程

| 步骤 | 用户所见 | 背后发生 |
|------|----------|----------|
| 1 | 用户点击右上角「🚀 发布」按钮 | — |
| 2 | 约 1 秒的加载动画 | Layer 1 后端：React Flow 连线图 → 代码生成 → 计算 Hash → Jachin 私钥盖章签名 → 打包 .jmp → 推送到市场 |
| 3 | 「发布成功」提示 | — |

**用户操作**：一次点击。

### 3.2 技术要点

- **内存中完成**：Next.js 后端在内存中接管全流程
- **零 CLI**：开发者/小白用户均无需接触命令行
- **自动签名**：私钥在 Layer 1 安全区，用户不可见

## 四、异常时的显性反馈

**原则**：正常情况下，密码学完全隐形。**只有检测到篡改时**才显性提示。

### 4.1 篡改拦截

当 Layer 2 校验 .jmp 发现 Hash 不匹配或签名无效时：

```
┌─────────────────────────────────────────────────────┐
│  🚫 安全拦截                                         │
│                                                      │
│  检测到该神经元模块可能已被污染，                     │
│  为了您的安全，已自动拦截加载。                      │
│                                                      │
│  [ 了解详情 ]  [ 关闭 ]                              │
└─────────────────────────────────────────────────────┘
```

「了解详情」可展开技术信息（供极客或运维排查），默认折叠。

## 五、与 P0 信任链的映射

| P0 技术组件 | 用户无感部分 | 用户可见部分 |
|-------------|--------------|--------------|
| Ed25519 签名 | 私钥盖章、公钥验真 | 无 |
| content_hashes | 自动计算与校验 | 无 |
| 公钥下发 | 配对时自动完成 | 6 位码 / 二维码 |
| 权限注入 | WASI 按授权配置 | 大白话卡片 + 一键安装 |
| 篡改检测 | 静默校验 | 仅异常时弹窗 |

---

## 六、实施优先级

| 机制 | 依赖 | 优先级 |
|------|------|--------|
| 傻瓜式绑定 | 配对协议、公钥安全存储 | P0（与心跳、Console 联动） |
| 权限大白话 | manifest 解析、权限映射表 | P1（Market 部署流程） |
| 云端无感打包 | Forge 编译引擎、签名管线 | P1（Forge 发布闭环） |
| 篡改拦截提示 | Layer 2 验签逻辑 | P0（与信任链同步） |
