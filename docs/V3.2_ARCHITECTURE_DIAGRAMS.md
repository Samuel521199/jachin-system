### 图 B: 大小脑路由逻辑 (Big-Little Brain Routing)

任务按复杂度分流，确保「杀鸡不用牛刀」。

```mermaid
sequenceDiagram
    participant User
    participant Edge as Tier 3 (Edge)
    participant Router as Tier 2 (Model Router)
    participant SmallBrain as CPU Model (Qwen-1.8B)
    participant BigBrain as GPU Model (Qwen-72B)
    participant Cloud as Tier 1 (GPT-4)
    participant Skill as Skill Actor

    User->>Edge: "帮我查一下天气"
    
    alt Edge Reflex (极简)
        Edge->>Edge: 本地正则/SLM 匹配
        Edge-->>User: (直接调用API) "25度"
    else Complexity Check (普通)
        Edge->>Router: 发送请求
        Router->>Router: 复杂度评估 (Score < 0.3)
        Router->>SmallBrain: 路由给 CPU 模型
        SmallBrain->>Skill: 调用 WeatherSkill
        Skill-->>User: 返回结果
    else Heavy Reasoning (困难)
        Edge->>Router: "帮我写个贪吃蛇游戏"
        Router->>Router: 复杂度评估 (Score > 0.8)
        Router->>BigBrain: 路由给 GPU 模型
        BigBrain->>Skill: 调用 CodingSkill
        Skill-->>User: 返回代码
    end
```

### 流程说明

- **Edge Reflex**: Tier 3 本地 SLM/规则引擎处理极简指令，无需 Tier 2 介入
- **Model Router**: Tier 2 入口根据 `estimate_complexity_score(query)` 路由：Score < 0.3 → SmallModel，> 0.8 → CloudModel
- **Swarm Scheduler**: 根据 `capability.compute` (cpu_light | gpu_heavy) 将任务分配到对应 Ray Node

## 1. Jachin Link 连接流程 (The Stealth Connection)

### 序列图

```mermaid
sequenceDiagram
    participant User as Tier 3 (Client)
    participant Cloud as Tier 1 (Auth/Relay)
    participant Hive as Tier 2 (Home Server)

    Note over User, Hive: 首次配对 (The Only Scan)
    Hive->>Hive: 生成 CA 根证书 & 邀请码
    User->>Hive: 扫描二维码 (获取 Server IP + Token)
    User->>User: 生成 RSA 私钥 (硬件绑定)
    User->>Hive: 发送 CSR (证书签名请求)
    Hive->>Hive: 验证 Token -> 签发 Client 证书
    Hive->>User: 返回 Client 证书 (永久有效)

    Note over User, Hive: 日常连接 (Zero Trust)
    User->>User: 检测网络环境
    alt 局域网 (LAN)
        User->>Hive: gRPC 直连 (mTLS 握手)
    else 广域网 (WAN)
        User->>Cloud: 连接中继节点
        Cloud->>Hive: 转发加密流量 (Cloud 无法解密)
    end
    Hive->>User: 连接建立 (握手成功)
```

### 流程说明

#### 首次配对阶段（The Only Scan）
1. **Tier 2 (Hive)** 生成自签名 CA 根证书和配对二维码
2. **Tier 3 (User)** 扫描二维码，获取 Server ID 和临时 Token
3. **Tier 3** 在本地生成 RSA 私钥（硬件绑定）
4. **Tier 3** 生成 CSR（证书签名请求）并发送给 Tier 2
5. **Tier 2** 验证 Token 有效性，签发客户端证书
6. **Tier 2** 返回客户端证书（PEM 格式），永久有效

#### 日常连接阶段（Zero Trust）
1. **Tier 3** 检测当前网络环境
2. **局域网场景**：
   - 使用 mDNS 发现 Tier 2
   - 直接建立 gRPC over HTTPS 连接
   - mTLS 双向认证
3. **广域网场景**：
   - 连接 Tier 1 中继节点
   - Tier 1 转发加密流量（端到端加密，无法解密）
   - 最终到达 Tier 2
4. **连接建立**：mTLS 握手成功，开始传输 AI 指令

## 2. 插件商业闭环流程 (The Economy Loop)

### 流程图

```mermaid
graph LR
    Dev[开发者] -->|上传/定价| Market[Tier 1 商城]
    Market -->|安全扫描/签名| Market
    User[用户] -->|浏览/付费| Market
    Market -->|分账 (70/30)| Dev
    Market -->|下发 .jsp + License| Hive[Tier 2 本地]
    Hive -->|验证签名| Installer[插件管理器]
    Installer -->|部署隔离环境| Ray[Ray Worker]
    Ray -->|每日心跳验证| Market
```

### 流程说明

#### 开发者侧
1. **开发者** 上传插件包（.jsp）到 Tier 1 Market
2. **开发者** 设定价格（免费/一次性/订阅）
3. **Tier 1 Market** 进行安全扫描和代码审核
4. **Tier 1 Market** 添加官方签名（`developer_signature`）
5. 插件上架，等待用户购买

#### 用户侧
1. **用户** 在 Tier 1 Market 浏览插件
2. **用户** 付费购买（或选择免费插件）
3. **Tier 1 Market** 生成 License Key
4. **Tier 1 Market** 下发 .jsp 包和 License Key 到 Tier 2

#### Tier 2 侧
1. **插件管理器** 接收 .jsp 包
2. **插件管理器** 验证 Tier 1 官方签名
3. **插件管理器** 验证 License Key（付费插件）
4. **插件管理器** 解压插件到 `skills_repo/`
5. **插件管理器** 创建 Ray RuntimeEnv（隔离环境）
6. **Ray Worker** 运行插件代码
7. **Ray Worker** 定期向 Tier 1 Market 发送心跳验证 License

#### 商业模式
- **分账比例**: 开发者 70%，平台 30%
- **License 验证**: 每日心跳，确保 License 有效
- **DRM 机制**: License 过期或退款时，自动停止插件运行

## 4. 数据流图

### AI 指令处理流程

```mermaid
sequenceDiagram
    participant Client as Tier 3 Client
    participant Gateway as Jachin Link Gateway
    participant Brain as Jachin Brain
    participant Ray as Ray Cluster
    participant Memory as Federated Memory

    Client->>Gateway: InvokePlugin (gRPC + mTLS)<br/>plugin_id, method_name, payload
    Gateway->>Gateway: 验证客户端证书
    Gateway->>Brain: 转发插件调用请求
    Brain->>Brain: 根据 plugin_id 查找 Ray Actor
    Brain->>Ray: 调用插件方法 (动态分发)
    Ray->>Ray: 执行插件逻辑 (GPU/NPU)
    Ray->>Memory: 查询/存储记忆
    Memory-->>Ray: 返回结果
    Ray-->>Brain: 插件响应 + UI Schema
    Brain-->>Gateway: PluginResponse<br/>payload + ui_render_schema
    Gateway-->>Client: PluginResponse<br/>(客户端动态渲染 UI)
```

## 5. 安全模型

### mTLS 双向认证流程

```mermaid
sequenceDiagram
    participant Client as Tier 3
    participant Server as Tier 2 Gateway

    Note over Client, Server: TLS 1.3 Handshake
    
    Client->>Server: ClientHello + 支持的密码套件
    Server->>Client: ServerHello + Server Certificate
    Client->>Client: 验证 Server Certificate (CA 签名)
    Client->>Server: Client Certificate + ClientKeyExchange
    Server->>Server: 验证 Client Certificate (CA 签名 + 设备 ID)
    
    alt 验证通过
        Server->>Client: Finished (握手成功)
        Note over Client, Server: 开始加密通信
    else 验证失败
        Server->>Client: Alert (连接拒绝)
    end
```

## 6. 插件生命周期

### 插件安装到运行流程

```mermaid
stateDiagram-v2
    [*] --> 上传: 开发者上传 .jsp
    上传 --> 审核: Tier 1 安全扫描
    审核 --> 上架: 审核通过
    审核 --> 拒绝: 审核失败
    上架 --> 购买: 用户浏览
    购买 --> 下载: 付费完成
    下载 --> 验证: Tier 2 接收
    验证 --> 安装: 签名验证通过
    验证 --> 拒绝: 签名验证失败
    安装 --> 运行: 部署到 Ray
    运行 --> 心跳: 定期验证 License
    心跳 --> 运行: License 有效
    心跳 --> 停止: License 过期
    停止 --> [*]
```
